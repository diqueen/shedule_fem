# Telegram-бот с расписанием СПбГТИ(ТУ) / ФЭМ

Production-ready Telegram-бот, который берёт **месячное** расписание с официального сайта
[gtifem.ru/dekanat/raspisanie](https://gtifem.ru/dekanat/raspisanie/), нормализует его,
хранит в PostgreSQL, кэширует и отдаёт студентам — по запросу и автоматически каждый вечер.

## Возможности

- Регистрация в боте: **уровень обучения → факультет/направление → курс → группа**.
- Команды просмотра: `/schedule`, `/tomorrow`, `/week`, `/month`, `/settings`, `/help`.
- Автоматическая рассылка расписания на завтра в заданное время (`SCHEDULE_SEND_TIME`).
- Учёт часового пояса `Europe/Moscow` (а не локального времени сервера).
- Один запрос к сайту на группу — сколько бы пользователей в ней ни было.
- Кэш месячного расписания с настраиваемым TTL и принудительным `/refresh`.
- Отказоустойчивость: при недоступности сайта используется последняя корректная версия данных.
- Защита от повторной отправки (таблица `notification_log`), корректная обработка
  заблокировавших бота пользователей.
- Полностью типизированные SQLAlchemy 2.x модели + миграции Alembic.

## Архитектура

```
Telegram  →  Handlers  →  Services  →  Repositories  →  PostgreSQL
                                ↑
Сайт  →  Parser (client + parser)  →  ScheduleService  →  Cache / PostgreSQL
```

Ключевой принцип: **обработчики Telegram не парсят HTML**. Вся работа с сайтом изолирована в
`app/parser/`. Если сайт изменится — правится только парсер.

```
app/
├── bot/
│   ├── handlers/      # start, registration, schedule, settings, admin
│   ├── keyboards/     # inline-клавиатуры
│   ├── middlewares/   # внедрение сервисов и профиля пользователя
│   ├── container.py   # контейнер зависимостей
│   └── states.py      # FSM-состояния
├── parser/            # client.py (HTTP), parser.py (HTML), models.py, exceptions.py
├── services/          # schedule_service, notification_service, user_service, cache_service
├── database/          # models.py, database.py, repositories.py
├── scheduler/         # jobs.py (ежедневная рассылка + периодическое обновление)
├── utils/             # dates, formatting, hashing
├── config.py
└── main.py
tests/                 # pytest: парсер, БД, даты, рассылка
migrations/            # Alembic
scripts/               # download_and_parse.py, fetch_fixtures.py
Dockerfile, docker-compose.yml, pyproject.toml, .env.example
```

## Как работает парсер (результаты исследования сайта)

Сайт — Bitrix-страница, которая подгружает данные через **POST-запросы на тот же URL**
(`/dekanat/raspisanie/`). Контракт (получен из JS-компонента `gtifem:timetable.new`):

| POST-параметры | Ответ |
|---|---|
| `special`, `course` | JSON-список групп `[[name, id], ...]` |
| `special`, `course`, `group` | JSON-список месяцев `["сентябрь", "октябрь"]` |
| `special`, `course`, `group`, `month` | HTML-фрагмент с таблицей расписания |

Важные факты, проверенные на реальных данных:

- **`data-day`** — это **день месяца** (в шапке таблицы ячейки `id=dayN` содержат `«5 Октября»`).
  Год восстанавливается как ближайший к текущей дате (корректно обрабатываются переходы месяца/года).
- **`data-group`** — код группы (например `6511,6512`). На этом сайте он же служит названием
  группы; используется как `group_id` и как `group_name`.
- **`data-month`** — название месяца (`октябрь`). Таблица состоит из нескольких недельных блоков,
  каждый со своей строкой-заголовком.
- **`data-not`** — статус/примечание. Во всех проверенных записях пусто; сохраняется в поле `note`
  на будущее.
- **`.number`** (например `(21)6`) — служебная информация сайта, назначение не подтверждено,
  поэтому сохраняется как `source_number` и не используется как номер пары.
- **Тип занятия** определяется по суффиксу предмета: `(лек)`→лекция, `(пр)`→практика,
  `(лаб)`→лабораторная, `(сем)`→семинар, `(курс. раб)`→курсовая работа. Исходное название
  всегда сохраняется в `subject_raw`.
- **Преподаватель** извлекается из `<td>` после удаления `.subject`, `.aud`, `.number`.
  Плейсхолдеры (`. .`) превращаются в `None`.
- **Пустые ячейки** (без предмета) пропускаются — это не «занятие без названия», а заглушки.
- Расписание публикуется **на месяц**, поэтому данные грузятся и кэшируются помесячно.

> **Зеркало.** В некоторых сетях `gtifem.ru` недоступен напрямую. В `.env` можно указать
> резервные адреса (`SCHEDULE_URL_FALLBACKS`), например рабочее зеркало
> `https://gtifem.technolog.edu.ru/dekanat/raspisanie/`. У зеркала просрочен сертификат,
> поэтому по умолчанию `SCHEDULE_TLS_VERIFY=false`.

## Стек

Python 3.12+, aiogram 3.x, SQLAlchemy 2.x (async) + asyncpg, Alembic, APScheduler,
httpx + BeautifulSoup4 + lxml, pydantic-settings. Хранилище — PostgreSQL, кэш — локальный TTL.

## Быстрый старт (Docker)

### 1. Создать бота в BotFather

1. Откройте Telegram, напишите [@BotFather](https://t.me/BotFather).
2. Команда `/newbot`, задайте имя и username бота.
3. Скопируйте выданный **токен** вида `123456789:AA...`.

### 2. Создать `.env`

```bash
cp .env.example .env
```

Заполните минимум:

```env
BOT_TOKEN=123456789:AA...
ADMIN_IDS=ваш_telegram_id
```

Свой Telegram ID можно узнать у [@userinfobot](https://t.me/userinfobot).

### 3. Запустить

```bash
docker compose up -d --build
docker compose logs -f bot
```

`docker-compose.yml` поднимает `postgres` и `bot`; entrypoint ждёт БД, применяет
`alembic upgrade head` и запускает бота.

## Локальный запуск (без Docker)

```bash
python -m venv .venv
# Windows: .venv\Scripts\activate
source .venv/bin/activate
pip install -e ".[dev]"

cp .env.example .env   # укажите BOT_TOKEN и DATABASE_URL на свою БД
alembic upgrade head
python -m app.main
```

Нужна доступная PostgreSQL. Для быстрой проверки без Postgres можно указать
`DATABASE_URL=sqlite+aiosqlite:///./local.db` (таблицы создадутся автоматически).

## Переменные окружения

| Переменная | Назначение | По умолчанию |
|---|---|---|
| `BOT_TOKEN` | токен Telegram-бота | — |
| `DATABASE_URL` | строка подключения SQLAlchemy async | `postgresql+asyncpg://postgres:postgres@postgres:5432/schedule_bot` |
| `TIMEZONE` | часовой пояс приложения | `Europe/Moscow` |
| `SCHEDULE_SEND_TIME` | время ежедневной рассылки `HH:MM` | `20:00` |
| `SCHEDULE_CACHE_TTL` | TTL кэша месяца, сек | `3600` |
| `SCHEDULE_URL` | основной источник | `https://gtifem.ru/dekanat/raspisanie/` |
| `SCHEDULE_URL_FALLBACKS` | резервные зеркала через запятую | — |
| `ADMIN_IDS` | Telegram ID админов через запятую | — |
| `LOG_LEVEL` | уровень логирования | `INFO` |
| `DEBUG_HTML_DIR` | куда сохранять HTML при ошибке парсинга | — |
| `SCHEDULE_TLS_VERIFY` | проверять TLS-сертификат сайта | `false` |

## Миграции

```bash
alembic upgrade head          # применить
alembic revision --autogenerate -m "message"  # новая миграция
alembic downgrade -1          # откатить одну
```

## Тестирование

```bash
pytest -q
```

Тесты парсера работают на локальных фикстурах (`tests/fixtures/`) и **не требуют сети**.
Покрыты: парсинг таблицы и всех полей ячейки, отсутствие `.subject`/`.aud`/преподавателя,
несколько преподавателей и групп, `data-not`, некорректные даты/время, неизвестная структура,
работа с БД (создание/поиск/смена группы/уведомления), переходы месяца и года, рассылка
(успех, повтор, блокировка, ошибка Telegram).

Обновить фикстуры с реального сайта:

```bash
python scripts/fetch_fixtures.py
```

Проверить парсер «вживую»:

```bash
python scripts/download_and_parse.py --list-catalog
python scripts/download_and_parse.py --special "Экономика" --course 2 --group "6511,6512"
```

## Просмотр логов

```bash
docker compose logs -f bot
```

Логируются: запуск бота, подключение к БД, начало/завершение загрузки расписания,
количество групп и записей, обновление кэша, старт/финиш рассылки и все исключения.
**Секреты (`BOT_TOKEN`, пароль БД) не логируются.**

## Команды

**Пользовательские**

| Команда | Действие |
|---|---|
| `/start` | регистрация и главное меню |
| `/schedule` | ближайший день с занятиями (сегодня или вперёд) |
| `/tomorrow` | расписание на завтра |
| `/week` | расписание на текущую неделю (Пн–Вс) |
| `/month` | расписание на текущий месяц |
| `/settings` | группа и уведомления |
| `/help` | справка |

**Административные** (только для ID из `ADMIN_IDS`)

| Команда | Действие |
|---|---|
| `/stats` | статистика: пользователи, группы, записи, кэш, состояние источника |
| `/refresh` | принудительно обновить расписание текущего месяца |

## Отказоустойчивость

- **Сайт недоступен** → используется последняя корректная версия из PostgreSQL
  (сообщение помечается «используются последние доступные данные»), ошибка пишется в лог
  и в `schedule_fetch_log`. Старые данные не удаляются.
- **Нет данных вообще** → пользователю показывается сообщение о недоступности источника,
  а не «занятий нет».
- **Различаются состояния**: `нет занятий` (данные получены, записей на дату нет),
  `расписание не опубликовано` (месяц пуст), `ошибка получения` (источник недоступен).
- **Парсер «сломался»** (0 записей там, где раньше были) → это трактуется как ошибка структуры,
  старые данные сохраняются.
- **Ошибка отправки одному пользователю** не прерывает рассылку остальным.
- **Пользователь заблокировал бота** → уведомления автоматически отключаются.
- **Повторный запуск scheduler** не отправит сообщение дважды (уникальность `user_id + schedule_date`).

## Что делать при изменении структуры сайта

1. Запустите `python scripts/download_and_parse.py --list-catalog` и проверьте ответы.
2. Сравните фактическую разметку с ожиданиями в `app/parser/parser.py`
   (`parse_catalog`, `parse_month_html`) и контракт запросов в `app/parser/client.py`.
3. Обновите только слой `app/parser/` — остальной код (handlers, БД, рассылка) не затрагивается.
4. Обновите фикстуры (`scripts/fetch_fixtures.py`) и прогоните `pytest`.

## Примечания

- Расписание публикуется помесячно; доступные месяцы определяются сайтом динамически.
- Кэш — процесс-локальный (без Redis): PostgreSQL хранит нормализованные данные, TTL-кэш лишь
  экономит запросы к сайту. Этого достаточно для одного экземпляра бота.
